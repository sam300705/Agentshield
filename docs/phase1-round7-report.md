## Compatibility and security boundaries

The canonical action identity function returns a sensitive hash preimage. Do not log, persist or display it. Persist only its SHA-256 digest and sanitized evidence at display/storage boundaries. Existing `agent-action@2` digests intentionally cannot satisfy new action requests: preserve historical rows and request a fresh independently reviewed action with a new idempotency key. Never rewrite historic approvals, event hashes, receipts or migration history.

No new database migration or lockfile change is needed. Fresh approval requests record sanitized evidence in the existing immutable audit transaction. Legacy queue entries without a matching evidence snapshot remain visible, with approval disabled and a fresh-request message. Their rejection remains available to authorized independent reviewers. `expectedActionDigest` is an optional backward-compatible API review field; dashboard reviews supply it, and the transactional update also binds the current stored digest. API middleware continues to enforce role/tenant access and service logic prevents self-review.

The legacy finding queue's pagination fields/data are preserved; `agentApprovals` has its own page/limit/total/data. Dashboard pending count is the sum of both models. Stable requestedAt/id ordering and bounded audit lookup prevent unbounded response work. Stale frontend queue responses cannot replace newer page state.
